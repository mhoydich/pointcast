# Area readability audit: Baby Bonfire, Coast Commons, House Channel, Light Companion

2026-11-11. Run it again with `npm run audit:areas`. `tests/area-readability.test.mjs` runs it in `npm test`.

## What was checked

Every `index.html` under `public/baby-bonfire`, `public/coast-commons`, `public/house` and `public/light`: 52 files. 50 are public pages (28 Baby Bonfire, 19 Coast Commons, 2 House Channel, 1 Light Companion). Two are private and were checked the other way round: `/house/r/` (the phone remote) and `/light/circle/` (the one file that serves every `/light/c/<id>` circle page; the brief called it `/light/c/`).

For each public page, from the files in the repo (nothing is fetched):

1. `lang="en"`, a viewport tag, exactly one h1.
2. A title, unique across the set.
3. A meta description of 70 to 160 characters, unique across the set.
4. An absolute canonical with a trailing slash that matches where the file lives.
5. Open Graph: title, description, url (same as canonical), type, site_name, image, image:width 1200, image:height 630, image:alt.
6. Twitter: card `summary_large_image`, title, description, image, image:alt.
7. One JSON-LD block that parses, with `@context`, `@type` (WebPage, CollectionPage or CreativeWork), name, description and url equal to the canonical. No Product, Offer, Review, AggregateRating, MedicalWebPage, price or offers.
8. A `rel="alternate" type="application/json"` link to the area's JSON twin.
9. No robots noindex, and alt on every img.
10. A card: an absolute URL on pointcast.xyz to a file that exists in `public/` and is a 1200x630 PNG.
11. A word check on the head text, alt text and JSON-LD: no cannabis or company names, prices, calls to buy, unnegated "for sale", first person, health claims or remote real flame.

Discovery: the page is in `sitemap-discovery.xml.ts`; in `llms-full.txt`; main pages and each hub's twin are in `llms.txt`; each hub and twin is in `agent-surfaces.ts`; each page has a url, title and summary in its twin's `pageIndex`; `robots.txt` has a Sitemap line for `sitemap-discovery.xml`. The private routes must say noindex and appear in no sitemap, llms file, agents index or twin.

## What was fixed

- **Cards.** 20 new 1200x630 PNGs: six Baby Bonfire pages (open-spec, open-mesh, barter-board, make-a-piece, first-place, prayer) and fourteen Coast Commons town pages. They use the existing drawings (the street, the mesh, the coast strip). No drawing code changed and no existing card was redrawn. The fourteen town cards share one picture and differ in their words; Light Companion keeps its existing `/light/card.png`.
- **Descriptions, site_name and JSON-LD.** Wording lives in `scripts/unfurl-cards/seo.mjs`. `stampHead` and `shareHead` in `cards.mjs` write the meta description, `og:site_name` and the JSON-LD block, so `npm run og:area-cards` keeps all of it in step and `--check` fails if it drifts. The Coast Commons generators read the same file. `/light/` is hand-edited, since it has no card entry.
- **Twins.** Each of the four JSON twins has a `pageIndex` of url, title and summary for every public page. The three hand-written ones are written by `build.mjs`; Coast Commons' by its generator. `public/house.json` no longer lists the phone remote.
- **Indexes.** `llms.txt` gets Baby Bonfire and Coast Commons entries and the House hub. `llms-full.txt` gets a section listing every page, and no longer names `/house/r/`. `agent-surfaces.ts` gets the House hub.
- **h1.** `/house/` had none; the "HOUSE CHANNEL" mark is now the h1. `/baby-bonfire/light-the-hearth/` had none; its header mark is now the h1. Each has one CSS tweak so nothing changes visually.
- **Sitemap.** `sitemap-discovery.xml.ts` already listed every public page and no private route, and `robots.txt` already had `Sitemap: https://pointcast.xyz/sitemap-discovery.xml`, so neither changed. `sitemap-index.xml` is generated by `@astrojs/sitemap` (it lists the generated `sitemap-0.xml`) and is not written by hand in this repo, so it was left alone. The robots.txt line is how a crawler reaches the discovery sitemap.
- **Tests.** Two existing tests (`baby-bonfire-prayer`, `light-companion`) refuse any outside URL; the JSON-LD `@context` (schema.org) tripped them, so they now skip the JSON-LD block. `unfurl-cards.test.mjs` lists the 20 new cards. `atlas.json` and `atlas/index.json` were regenerated.

## What cannot be verified from source

- How Messages, X, Slack and Discord draw the cards. The tags and files are correct; each app caches and crops in its own way. Paste a page into each after deploy.
- Whether Google or Bing has indexed any of these pages, or will show the descriptions. Source cannot say.
- That the live site serves what the repo has: the checks read files, and Cloudflare Pages rewrites some heads at build time (`src/lib/seo-build.mjs`). The build was not run here.
- That `/light/c/<id>` responses carry noindex. The Pages Function in `functions/light/c/` serves the shell in `public/light/circle/`, which has the meta tag; its response headers were not read.
- That `sitemap-index.xml` on the live site does not list the discovery sitemap. Crawlers reach it through robots.txt.
