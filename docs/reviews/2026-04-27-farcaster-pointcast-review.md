## What the docs imply

Farcaster Mini Apps are ordinary web apps that become native-feeling inside Farcaster clients through three requirements:

1. A domain-level manifest at `/.well-known/farcaster.json`.
2. Page-level `fc:miniapp` embed metadata for shareable cards.
3. Runtime SDK integration, especially `sdk.actions.ready()` so the Farcaster splash screen clears.

Farcaster splits discovery from sharing:

- Manifest: app identity, author verification, discovery, app adds, notifications.
- Embed: the specific page card shown inside the feed.

That distinction matters for PointCast because PointCast is already a network of rooms and blocks. One manifest can identify the app, while multiple pages can become rich Farcaster launch surfaces over time.

## Current PointCast state

PointCast is already unusually close to a good Farcaster-native product:

- `/drum` uses `DrumLayout`, emits an `fc:miniapp` embed, imports `@farcaster/miniapp-sdk`, and calls `sdk.actions.ready()`.
- Required assets exist at valid sizes:
  - `public/images/drum-icon.png`: 1024x1024 RGB PNG
  - `public/images/drum-splash.png`: 200x200 RGB PNG
  - `public/images/drum-og.png`: 1200x630 RGB PNG
- `@farcaster/miniapp-sdk` is already installed.
- The old Frames v1 path is documented as deprecated, which is the right strategic call.
- The site already has strong machine-readable primitives: JSON block routes, feeds, `agents.json`, `llms.txt`, and agent-mode HTML.

## Gaps

1. `/.well-known/farcaster.json` was missing. Without it, the app can be shared but cannot be properly verified, added, discovered, or notification-enabled.
2. `accountAssociation` still needs to be generated by the Farcaster Developer Tools for `pointcast.xyz` and provided to the build as `FARCASTER_ACCOUNT_ASSOCIATION`.
3. `/drum` calls `ready()`, but it does not yet use Farcaster context to identify the user, prefill the local drum name, or expose a Farcaster-native share action.
4. PointCast still has old `fc:frame` references in shared layouts and docs. Some are acceptable backward-compatibility tags; some copy still describes v1 Frames as if they might work.
5. The best PointCast/Farcaster play is not "one mini app." It is a small social client pattern: rooms, blocks, casts, agents, and local channels stitched together by Farcaster identity.

## Implementation shipped in this pass

Added `src/pages/.well-known/farcaster.json.ts`.

The route now publishes a PointCast Drum Mini App manifest with:

- `miniapp.version`
- name, home URL, icon, splash image, splash background
- social/music category metadata
- `actions.ready` and `actions.composeCast` capabilities
- `canonicalDomain`
- optional signed `accountAssociation` loaded from `FARCASTER_ACCOUNT_ASSOCIATION`

The route stays valid JSON before signing. It becomes Farcaster-verifiable after the account association is generated and added.

## Recommended product direction

Build "better Farcaster" as PointCast's own client layer, not as a clone.

The sharp version:

- Farcaster supplies identity, graph, distribution, casts, and mini-app discovery.
- PointCast supplies rooms, durable blocks, agent-readable feeds, local context, Tezos objects, creative rituals, and small-group presence.

Prioritize these surfaces:

1. Drum as the first flagship Mini App.
2. Blocks as cast-native objects: every `/b/{id}` gets a clean embed and a compose action.
3. A PointCast Farcaster session layer using Quick Auth for trusted per-FID actions.
4. A lightweight "cast into PointCast" flow: compose a block, publish to PointCast, then open Farcaster compose with the block URL embedded.
5. A Farcaster-aware home view: show recent casts by `@mhoydich`, featured PointCast blocks, and room presence together.

## Next build steps

1. Generate the account association:
   - Open https://farcaster.xyz/~/developers/mini-apps/manifest
   - Enter `pointcast.xyz`
   - Sign with the owning Farcaster account
   - Store the resulting JSON as `FARCASTER_ACCOUNT_ASSOCIATION`
2. Validate:
   - `https://pointcast.xyz/.well-known/farcaster.json`
   - `https://pointcast.xyz/drum`
3. Add Farcaster context to `/drum`:
   - read `sdk.context.user`
   - set `pc:drumName` from username/display name
   - show a `composeCast` share action only inside Mini App context
4. Add Quick Auth only where actions need trust. Context is fine for display; Quick Auth is the server-trust boundary.
5. Convert `/b/{id}` pages from legacy Frame copy to modern Mini App/card language.
