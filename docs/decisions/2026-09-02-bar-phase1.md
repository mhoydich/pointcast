# Bar phase 1: lighter strip, caused bursts, measured utility

Date: 2026-09-02  
Status: implemented on `codex/bar-phase1-bursts-20260902`; not deployed

## Direction

Mike's current direction is the constraint:

> "that might be too much for the bar, it'd be neat that it had say some animations or effects that show up on the site, etc, bursts, and yah utility, etc, feel free to rethink and begin the next phase."

The longer arc remains a mix of "real utility, entertainment, innovation" and, "once we get to stability we want to start thinking innovation."

Phase 1 therefore subtracts unfinished surface area, gives the live tools a visible site-wide consequence, and adds measurement before adding more permanent kit.

## What changed

- The fixed strip now carries six live stamps: `01 ROOM`, `02 ASK`, `03 AGENT`, `06 CAST`, `07 PASSPORT`, and `08 SEISMO`.
- `04 FED` and `05 BROADCAST` keep their implementation and stable numbers, but move into the ≡ tray under `WORKBENCH · COMING`. Existing ⌘4 and ⌘5 access remains; the live stamps keep their original ⌘ numbers rather than being renumbered by visible position.
- ROOM opens a small second WebSocket to the global presence object. Cursor/chat stays in its existing per-route object; the second connection carries only the shared site-wide burst tail.
- `SpellLayer` renders every fresh burst as a 900 ms radial pulse starting at the dock in the supplied channel colour. Mint adds existing confetti, a newly answered ping adds the existing cat, and CAST reuses `confetti`, `rain`, `cat`, or `breath`. Reduced-motion visitors get the ticker without the animated pulse.
- The dock ticker shows one caused line for five seconds, for example `tz2Fj…xdFw minted Sitting 02 · 12s ago`.
- CursorRoom chat entries now receive a server-assigned `id`. A connected sender shows the cursor bubble immediately but waits for the identified server echo before appending to the log. `sid|at|msg` remains the fallback key for payloads from old peers.
- Tug polling starts only while `#pc-tug` intersects the viewport. A hidden tab uses a 30-second network cadence and stops the one-second paint timer. SEISMO stops its animation frame loop while hidden and resumes only if its tray is still open.
- The existing analytics endpoint receives full-weight `dock` events for `tray_open`, `stamp_action`, `burst_seen`, and `say_sent`. `score-live.mjs` counts those events at `/dock`; `score-projects.mjs` now has a PointCast Dock row with the relevant source files.

## Burst contract

```ts
type BurstKind = 'mint' | 'tug' | 'bell' | 'ping-answered' | 'cast';

type BurstEvent = {
  kind: BurstKind;
  at: number; // server epoch milliseconds
  by: { handle?: string; noun?: number };
  meta: Record<string, string | number | boolean>;
};
```

`POST /api/burst` forwards to the global `PresenceRoom`. The Durable Object assigns `at`, sanitizes identity and metadata, limits each client to one accepted submission per second, caps new broadcasts globally and by kind to one per second, and coalesces queued same-kind events. Only the 20 events that are actually broadcast are retained, in DO memory only. There are no burst KV writes.

Mint is the stricter path. The browser posts the confirmed operation hash only after Taquito's one-confirmation promise resolves. `/api/burst` then asks TzKT for that transaction and requires all three facts before forwarding: `status === "applied"`, target equals the Kennel Club contract, and entrypoint equals `mint`. The TzKT sender becomes `by.handle`; the client cannot choose the displayed minter. A briefly unindexed operation is retried by the mint feedback path and is never broadcast before verification.

Tug bursts originate inside the global DO when the decayed rope moves from inside to outside ±0.6. Bell Post and Bell Choir request `bell` bursts only for local visitor rings. ASK reconciliation requests `ping-answered` only on the transition from sent to answered. CAST requests go site-wide only for an explicit magic word or CAST stamp action while ROOM is on; mood auto-casts stay local.

## Weight measurement

Measurement method: UTF-8 byte length of the contents of every `<script is:inline>` element in `src/components/FooterBar.astro`, before Astro minification.

- Before: 74,369 bytes
- After: 74,366 bytes
- Change: -3 bytes

The ticker and analytics listener live in an Astro-bundled module (`DockBurstTicker.astro`), so this phase does not grow FooterBar's inline JavaScript. A regression test holds the baseline ceiling.

## Tests and release order

The root suite covers dock placement, stable shortcuts, echo behavior, idle gates, analytics/scoring, the byte ceiling, and TzKT mint verification. The presence Worker has its own fake Durable Object storage and fake WebSocket tests for server chat IDs, client/kind throttling, coalescing, the 20-event memory cap, zero burst storage writes, and tug threshold emission.

Production deploy order, when separately approved:

1. Deploy `workers/presence` first so `/burst` and server chat IDs exist.
2. Deploy Pages second so the new `/api/burst` proxy and clients begin using them.

This change does not deploy either surface.

## Phase 2 candidates

- Earned stamps on the stamps contract: make select utility or participation marks portable and verifiable while keeping high-frequency burst history ephemeral.
- Peer kit items: finish the data-only federation hook so a trusted peer can advertise a bounded kit item, with capability and provenance visible before install.

Both wait for real `/dock` usage and burst-seen data. Phase 1 creates the evidence needed to decide which deserves permanent bar space.
