# The station: task board for Opus and Sonnet

Date: 2026-09-21 · Owner of the board: cc (Claude Code, Fable 5.1) · Director: Mike

The music layer shipped over two days: the Music on shelf (`/#music-on`), the listening wall,
Mike Hoydich Radio (`/station`) with a play log, sourced liner notes, a request line for people
and agents (MCP `station_on_air` / `station_request`), the companion label in presence, a music
card on `/me`, Rewind, and a scripted ten-listener prototype (`/station/party`).

This board splits what comes next by the kind of work it is. **Opus gets judgment**: review,
architecture, anything where being wrong is expensive. **Sonnet gets well-specified builds**:
clear inputs and outputs, tests, no production access. Fable holds the thread, reviews every
PR from either, merges and deploys.

House rules for every task
- Fresh worktree off `origin/main` under `~/pc-<name>`. Never read or edit `~/pointcast` on disk.
- Explicit `git add <paths>`. One PR per task. Do not merge, do not deploy, do not write to
  production KV or call production write endpoints. Fable merges.
- Four tests fail on `main` and are not yours: the "New this week" seven-item contract, the
  four-pad Rosebud instrument, on-page SEO invariants, the current field edition.
- Any new MCP tool module must be added to `servedCatalogue()` in
  `tests/town-inspector-honesty.test.mjs`, or `/agents.json` honesty fails.
- `/auth` must stay free of Spotify/broadcaster copy and element ids; `/me` must stay free of
  element ids. Both are tested.
- Text on the station is counted or sourced. Nothing is generated and presented as fact.

## Next for Opus (judgment)

**O2 · Accounts ↔ profiles ↔ stations.** `/p/{handle}` pages are static, built from on-chain
profile objects, with no link to a signed-in account. Design the smallest link that lets a
signed-in person claim "this handle is mine" (the wallet that owns the profile object is
already linkable on `/me`), then what `/station/{handle}` means for a non-broadcaster: a
personal connection only has current-track scope by policy, so a personal station is a *live
card plus their request history*, not a play log, unless they opt into more. Deliver a design
note with the data model, the consent copy, the routes, and what must NOT be built.

**O3 · The listening party, for real.** Turn `/station/party` into a room with real presence.
The PresenceRoom Durable Object already carries `listening`, waves, vibes and `drum:*` signals.
Decide: what extra fields ride presence (tempo? decade? nothing beyond the label?), how
"two people on one artist" is detected without the server learning more than it must, how the
moments rate-limit themselves, and what the quiet/do-not-disturb control is. Deliver protocol
additions, a threat/abuse model, and a build plan cut into Sonnet-sized tasks.

**O4 · Receipts.** When a request is played, the requester could get a countersigned receipt
(the town already has `agent-payments/v1` receipts and a Tezos tower). Decide whether this is
a signed JSON receipt, a tower cast, or a soulbound stamp; who signs; what an agent does with
it. Mike holds every key: deliver a plan that stops at the signing step.

**O5 · Standing for agents.** An agent that recommends well should become known. Define
"standing" from public facts only (requests filed, requests played, ratio, first seen), how
self-reported names are kept from impersonating each other, and where it shows.

## Next for Sonnet (builds)

**S2 · The station ping.** A scheduled Worker that GETs `https://pointcast.xyz/now-playing.json`
every 10 minutes so the log fills when nobody is in town (today Spotify reported 130 minutes of
listening and the log caught one play). New worker dir under `workers/`, cron trigger, no
bindings, no secrets, logs only the status code. Include the KV-write cost in the PR body:
`resolveNowPlaying` stores the signal on every fresh fetch. Do not deploy.

**S3 · Share card for the station.** An OG image for `/station` and one for `/station/party`
in the hi-fi receiver look (dial, ON AIR lamp, LED wall), generated by a script the same way
`scripts/og-home-card.mjs` does the home card. Static art; no live data in the image.

**S4 · Phone pass.** `/station`, `/station/party` and the `/me` music card at 375 px: find and
fix overflow, tap targets under 44 px, the request form's field order, the polyrhythm wall's
name row. Screenshots before/after in the PR.

**S5 · Request line in Shortwave.** When a request is filed, post one line to the town square
(`/api/shortwave`, via `agent` or `page`) so the room sees it live; when it flips to played,
post the closing line. One extra KV write each: say so in the PR and gate it behind the same
hourly limit.

**S6 · `listening` on the square.** `/shortwave`'s "in town now" sidebar should show the ♫
label the attendance tray already shows. Read-only change.

**S7 · Rewind, year pages.** Once S1's import has real months in KV: `/station/2025`,
`/station/2024`… computed by the existing `computeStats` over that year's documents: top
artists and tracks *by play count* (the import has counts; Spotify's API does not), hours,
busiest day, longest streak, the first play of the year. Same textContent-only rendering rules.
