# PointCast 3D Drum Room — release contract

Date: 2026-07-22

## Outcome

`/drum-room` is a mobile-first shared 3D drum circle with invite-code rooms,
pleasant local Web Audio, anonymous Noun-style presence, reactions, native
sharing, and a downloadable 4:5 invite card. The explicit concurrency target
is 100 simultaneous visitors in one room.

## Realtime boundary

The browser sends sound instructions, never audio streams. A room hit is a
small pad/velocity/sequence message; every client synthesizes the voice
locally. This keeps bandwidth stable at 100 visitors and lets remote-event
gain fall as the crowd grows.

Each normalized room code maps to one `DrumRoomV2` Durable Object. The object
uses Cloudflare's WebSocket Hibernation API, connection attachments for
anonymous identity and rate state, SQLite for the total/recent hit history,
and ephemeral socket attachments for live presence.

Guardrails:

- 125 connection safety ceiling around the public 100-person target.
- 512-byte client frame ceiling.
- Six pad names and six reaction values are allowlisted.
- Eight messages/second/connection and 300 messages/second/room.
- Same-origin browser policy with localhost and Pages preview allowances.
- No account, wallet, microphone, location, profile, or chat text.

## Verification gates

1. `workers/pointcast-drum/npm run verify` passes strict types, current
   generated binding types, Workers-runtime protocol tests, a 100-socket test,
   and `wrangler deploy --dry-run`.
2. Root `npm test` and `npm run build:bare` pass.
3. Desktop and mobile browser QA covers entry with sound, quiet entry, all six
   pads, reaction, invite dialog, copied URL, downloaded card, drag camera,
   reduced-motion-safe layout, and CSS/WebGL fallback behavior.
4. The standalone load harness opens 100 WebSockets against the release URL,
   observes a 100-person presence snapshot, sends bounded hits, records
   broadcast latency, and reads the real stats endpoint.
5. Production truth requires all three: a `101` upgrade, a `welcome` payload,
   and a second client receiving a hit. A friendly HTTP 200 is not enough.

## Deployment order

The Worker ships first with both legacy `DrumRoom` and new `DrumRoomV2`
exports. Pages then ships with its external binding changed to `DrumRoomV2`.
This preserves the old class during the binding transition. The immutable
Pages URL and `pointcast.xyz` are verified against the exact published commit.
