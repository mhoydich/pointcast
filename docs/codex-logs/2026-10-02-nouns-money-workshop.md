Signed-in collections use existing session-owned D1 user_state, without a migration or new binding. Atomic per-note operations preserve concurrent collection and generic profile state; idempotent collection/removal retain original timestamps. Legacy KV initialization never overwrites a concurrent D1 winner. Writes require exact Origin and the displayed account ID as a consistency guard; the signed session remains authentication. Stale account changes cannot write into a newly signed account or paint its response into an older view. The anonymous collection is device-local; unavailable storage is explicitly visit-only. Device preferences are never silently imported into an account.

/nouns-money/pay is a browser-local IndexedDB workshop. It creates a test intent, selects one to five distinct artwork references, confirms one deterministic demo receipt, resumes open intents and cancels them. Demo selections do not consume the collection. All changes commit through an atomic transaction; repeated keys replay their original response, payload conflicts fail, terminal receipts cannot be replaced, and failed writes cannot report success. The dashboard reads actual local demo records, including a useful zero state. Sandbox history is browser-local and shared across sign-ins, explicitly stated in the interface. No HTTP payment endpoints, API keys or webhooks are invented.

The public catalog and account collection have an OpenAPI 3.1 specification. The small private TypeScript SDK includes collection/catalog HTTP clients and separate IndexedDB/memory sandbox adapters. The browser-ready ES module, TypeScript source and Node 24 example are runnable without a package publish. The documentation explains state, errors, idempotency, authentication boundaries, provenance, licensing boundaries and future issuer-sponsored Tezos collection architecture.
