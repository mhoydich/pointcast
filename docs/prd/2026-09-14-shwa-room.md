# Shwa — a little room for possibility

## Product direction

A place to think out loud and make things together. Shwa names both the room and its AI companion. PointCast is its home. Start on the web inside PointCast, then earn a native app through useful repeat visits. The current iteration prioritizes a large desktop board while retaining phone access. The same Shwa identity can also live on Industry Next; that second host is a future integration.

The scene is the main surface. Persistent controls are small: account, estimated cost, microphone/call, and tool navigation. Conversation outputs are temporary, useful objects: an image, cited research, a chart, a question, a vote, a survey, or a direction check. They can arrive after a short delay and remain scrollable for the current call.

## This release

- Five-human rooms: create a 24-hour invite, choose a name and resource preference, share text/image ideas, and vote on proposals. The server enforces five seats; reconnects preserve identity for 90 seconds, and explicit Leave releases a seat. Up to 40 shared pieces, 1,600 characters each. Votes are current participants’ preferences and never payment approval. Shared text reaches OpenAI only when a visitor selects Discuss with Shwa. Personal calls, audio, images, Spotify and wallet state remain per browser.

- One scrolling desktop board, with readable paper cards and all card actions beneath the paper. Pin, hide, and undo preserve drafts, choices, and pending research. Free examples remain available without opening the microphone or spending API credit.
- Functional backgrounds: Studio loosely spaces ideas over the island, Grid aligns them for comparison, Reading uses one generous text column, and Radio adds tunable waves. Modes preserve the call, drafts, generated images, and pending wallet work.
- Radio shows outgoing Shwa activity and incoming visitor activity from browser audio levels. Without a call it is labeled ambient visual preview. Visual wavelength, pause, and reduced-motion support are included. This is an interface visualization, not RF transmission or a claim to detect new frequencies.
- Image ideas and images sit at the upper right. Greenlight beneath the paper requests one image within the existing call quota; it is not a wallet payment or external approval. Generated images can be downloaded or applied as a temporary Studio backdrop. Prepared prompts survive starting a call.
- Voice overview explains the speak, respond, create, choose loop. An explicit local microphone test drives the Radio background without recording, uploading, or starting an OpenAI session. Closing the overview or starting a real call stops the preview microphone.

- PointCast route `/shwa/`, homepage entrance, and `/shwa.json` manifest.
- Supplied floating-island scene. Desktop image studio at the top right; compact call dock at the bottom; ideas collect over the scene.
- Phone layout with a persistent call dock, image preview, and Canvas / Images / Music sheets. Separate scroll areas, safe-area spacing, keyboard-aware image entry, reduced motion, and a transcript drawer.
- Existing PointCast cookie restores login. Shwa enters the universal sign-in screen and preserves a same-origin return path. GitHub OAuth is implemented in the shared menu and account desk, with explicit account linking and no repository or email scopes; production activation still requires a dedicated GitHub OAuth app and credentials.
- Optional personal Spotify consent using the existing registered callback and `user-read-currently-playing` scope. Credentials are encrypted per PointCast user. Returning users can restore the connection and current track. A separate Spotify player sign-in may still be needed; audio never autoplays. The shared broadcaster connection remains independent.
- Voice, live captions, interactive conversation cards, images, and cited research use the existing OpenAI gateway. Trial quotas and expiry are preserved; runtime availability is the source of truth. Images and research need an explicit click within an eligible call.
- Shwa receives bounded app context and visitor choices. Spotify metadata and audio remain outside model inputs. The room player is removed throughout a voice connection to avoid audio overlap.
- Estimated costs stay visible. x402 requires explicit wallet approval, and hiding the wallet retains pending requests and receipts. It does not automatically fund the OpenAI trial.

## The useful loop

1. Open a shared link; land in the scene without onboarding.
2. Tap once to call Shwa and approve the microphone in the browser.
3. Talk naturally. A relevant object arrives: a picture idea, a question, or something to adjust.
4. Tap Images or the corner preview to make and save an image. Return to the conversation without navigating away.
5. Pull up earlier objects or the live thread. Sign in to reconnect personal services when the call ends.

Success means a visitor can complete this loop on desktop and phone without hunting for call controls, losing a pending payment, or believing the AI sees services it cannot access.

## Next experiments, not shipped

- A stronger pocket sketchbook: save selected artifacts to an account, resume a room, and share a specific artifact with explicit privacy choices.
- Installable web app, then native iOS/Android once retention and session reliability justify it. Native audio routing, interruptions, background behavior, camera/video, push notifications, and purchase rules require their own implementation and testing.
- Group audio/video, collaborative games, modules, and a module store. Five-human shared-board proposal votes are live; original conversation-card surveys and votes still describe local preferences.
- Bring an existing AI/runtime through PointCast's connection system; do not imply consumer subscription credit transfers to API calls.
- Phone number/SIP entry, receiving paid call/image requests, funding budgets, and service payments as separate explicit flows. No telephone number or autonomous merchant funding exists in this release.

## Verification boundary

Automated fixtures prove session restoration, account isolation, OAuth state, token refresh failures, metadata separation, and player removal during calls. A real personal Spotify consent and playback round trip still needs the account owner. This release does not expand the capped voice experiment or automatically start paid calls.

## AI resources for a room

Each human chooses My AI, x402, or House account. This release records the choice and offers entry to the existing private AI profile or wallet. It does not proxy native runtimes into the room, turn a consumer subscription into API credit, or create a funded balance. The existing capped house OpenAI trial remains unchanged.

The next resource layer should support authenticated personal runtimes and explicit API purchases. A request names the action (voice, image, research or module), provider/model, requesting seat, payer, maximum amount, quote expiry and idempotency key. The payer reviews the quote or uses an explicitly configured scoped budget. After authorization, the server reserves funds, runs the bounded action, and records provider usage, payment receipt and settlement status. A timeout stays pending until reconciled; retrying must not pay twice. Other humans can propose an action, but cannot spend from another person’s account.

Funding the house, receiving payment for work, and buying another service are separate ledger operations. x402 receipts must bind the resource and price to the execution. Never put API keys, wallet secrets, private runtime job tokens or account metadata in room broadcasts. Sign-in can establish a verified participant identity later; current display names remain self-selected.
