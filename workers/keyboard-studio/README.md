# Keyboard Studio room service

Private `/keyboard` notes remain in browser storage. This service stores only passages that a visitor explicitly posts to a shared V3 room. The 32-character cryptographic room ID in the invitation URL is the bearer key: anyone with that link can read and add writing. Rooms cannot be listed.

`GET /api/keyboard-studio?room=<32 lowercase hex>` returns `{ "room": "…", "passages": [{ "id": "UUID", "name": "…", "text": "…", "at": 0 }] }` in creation order. A new room returns an empty array. GET includes an `ETag`; clients may poll with `If-None-Match` and receive 304 when nothing changed. `POST` to the same URL with JSON `{ "name": "…", "text": "…", "clientId": "UUID or 32 hex" }` returns `201 { "room": "…", "passage": { "id", "name", "text", "at" } }`. Generate a fresh `clientId` per passage and reuse it only when retrying that passage; an identical retry returns the original with 200, while a different payload under the same ID returns 409. `name` is at most 32 characters, `text` at most 3,000, request bodies at most 12,000 bytes, and rooms close to new passages after 200. Posts require same origin and are limited to 12 per minute per IP when `PC_RATES_KV` is bound. All responses disable caching and omit cross-origin access headers.

The Pages Function is `functions/api/keyboard-studio.ts`; it forwards to a separate SQLite Durable Object via the binding in root `wrangler.toml`. Deploy this Worker before deploying Pages so the `script_name` binding resolves. Direct public Worker requests return 404. Test the contract with `node --test tests/keyboard-studio-contract.test.mjs` from the repository root.

For an end-to-end local test after installing dependencies, run `npx wrangler dev` in this Worker directory, then run `npx wrangler pages dev .dist-build --do KEYBOARD_STUDIO=KeyboardStudioRoom@pointcast-keyboard-studio` from the repo root. Open the Pages URL and use the `/api/keyboard-studio` endpoint there. The Worker by itself intentionally serves no public room API.
