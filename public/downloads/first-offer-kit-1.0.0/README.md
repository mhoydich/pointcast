# First Offer Kit

**One useful thing. A clear offer. A real handoff.**

Version 1.0.0 · October 19, 2026 · PointCast · prepared with Codex

This free kit helps you describe a small digital product or a bounded service so a person — or an agent helping that person — can understand what they would get. You do not need a token, a wallet, a payment account, or a new business to use these files.

The kit is available now at USD 0. It contains local editable files. No account or payment is required. There are no scripts, tracking pixels, subscriptions, or automatic updates in the kit. Downloading it does not place an order or authorize an agent to spend money.

## Start here

Open `START-HERE.html` in a browser, or follow these steps:

1. **Choose one result you can deliver.** A poster for one event is easier to explain than “design help.” A printable game is easier to deliver than “community.”
2. **Fill in `worksheets/offer-worksheet.md`.** Name the person, the problem, the files, the boundaries, and what you need from them. Leave unknown terms visibly unresolved.
3. **Estimate the work.** Copy a blank row in `worksheets/cost-time-planner.csv`. Include preparation, delivery, and revisions. The examples are arithmetic, not evidence of what buyers will pay.
4. **Make a sample.** Use an original file you own. Remove private information. Check it on the device or printer the buyer is likely to use.
5. **Edit `templates/offer-page.html`.** The page is a draft by default. Replace every square-bracket placeholder, choose terms you can honor, and add a contact route you control. It has no payment or inquiry submission system.
6. **Make the two descriptions agree.** Update `templates/product.json` and `templates/agent.md` to match the page. These are PointCast template formats, not a published standard or a shopping-platform integration.
7. **Run `checklists/publish-and-accept.md`.** Ask one real person what they think they would receive. Fix the description before you offer it for sale.

## What is in the box?

- **A worksheet:** buyer, problem, deliverables, exclusions, price status, turnaround, revision limit, rights, and acceptance.
- **Three worked examples:** an event-poster service, an original printable activity pack, and product-card cleanup. They are fictional; their price guesses are not PointCast offers or market evidence.
- **An editable HTML page:** semantic headings, readable layout, keyboard focus, print styles, no JavaScript, no external dependencies.
- **Three original SVG cards:** simple geometric art, editable text and colors, and a visible fictional-example label.
- **A matching JSON + Markdown offer pair:** draft lifecycle, inquiry-only action, unresolved price and contact by default.
- **A cost/time CSV:** worked arithmetic plus blank rows for your own estimate.
- **Checklists and records:** acceptance, spending permission, and an unissued receipt template.

`manifest.json` lists every delivered file. `product.json` describes this free kit; it is separate from the draft product template in `templates/`.

## A small offer, explained well

“One event poster, delivered as a print PDF and a square image, using your final copy. One revision to the same design. No printing or logo design.”

That sentence gives a buyer something to inspect. Price, timing, rights, seller identity, cancellation, and support still need explicit terms. An agent should ask about missing terms instead of making them up.

## Working with an agent

An agent can help compare offers, draft a brief, or prepare a question. Preparing a purchase is different from approving it. Use `checklists/spending-permission.md` to record a person's limits. This plain-text checklist does not technically enforce those limits and is not AP2, ACP, or other protocol compliance.

Never paste passwords, payment credentials, private customer lists, or identity documents into these files. The receipt template is an empty record, not proof that anyone paid. Only a verified payment record can establish a payment's actual status.
